## 正文

### 一个很贵的瞬间

```
你:同时开着 4 个 Claude Code 会话,其中一个在跑 workflow,十几个子代理并行。
你(心想):让它们跑着,我先去回个消息。
40 分钟后你回来。
其中一个 agent:在你离开第 3 分钟时弹出了授权确认,一直没等到你。
```

整条流水线停了 37 分钟,而终端给你的全部提示,是一个转圈的光标。

这不是段子,是我自己的日常。问题出在 Claude Code 的一个机制上:**workflow 的运行状态,要到正常收尾才会写成一份完整可读的结果文件**。进行中的真相散落在事件日志(journal)和每个子代理的转录里 —— 都在你的电脑上,只是没人替你看。

### 我做了什么

一个 Claude Code 插件,叫 **Lucid**(开源:github.com/haixcoder/LUCID)。在任意会话里输入 `/lucid`,浏览器打开一个本地网页,2 秒刷新一次:

![仪表盘:每张运行卡含 phase 条与 agent 表](配图 1,占位)

- **每个 run 一张卡**:phase 进度、每个 agent 的状态 / 最近一次工具调用 / token 消耗 / 已经跑了多久;
- **点任意一行**:全宽抽屉展开**完整的** prompt 和结果 —— 是对转录做反向深扫拼出来的全文,不是截断预览;
- **会话监控**:所有会话(哪怕没有子代理)都会列出,并且它能分辨三种"等":**等你回答** / **疑似卡在授权** / **回合正常结束**。前两种置顶反白高亮,第三种安静待在原地 —— 执行完成 ≠ 等待输入,告警不该混为一谈。

![⏸ 等待高亮与全文抽屉](配图 2,占位)

### 不开浏览器,它也会来找你

服务后台有个通知线程,往**飞书**或任意通用 JSON webhook 推两类消息:workflow 到终态(完成/失败/终止)、以及会话开始等你。一次等待只推一条,重启不补发历史 —— 推送的目标很明确:**"它卡住了在等你"这件事,值得打断你。**

### 三条我给自己的硬规矩

1. **零依赖**:服务端只用 Python3 标准库,没有一行 pip 安装;前端预编译进单个 HTML,拿到即跑,没有构建步骤。
2. **只读、纯本机**:它不拦截、不注入、不修改 Claude Code 的任何行为 —— 只读 Claude Code 本来就写在你磁盘上的状态文件;服务只监听 127.0.0.1,你的数据不出这台机器。
3. **装完就消失**:会话开始自动检测、崩溃自动拉起(双触发口 + 常驻看护),日常只剩 `/lucid` 一个动作。

### 装一下

需要 macOS / Linux、Claude Code 2.0+、Python 3.9+。两行命令:

```
claude plugin marketplace add haixcoder/LUCID
claude plugin install lucid@kw-dev-plugins
```

界面自带中文 / English / Español / Français / Deutsch 五种语言、五种主题,项目筛选、全文搜索、通知配置都在 ⚙ 里。

### 最后

工具不大,但治的是"多开 Claude Code"之后一个真实存在的坑。代码、原理文档、回归测试都在仓库里 —— 尤其欢迎一种反馈:**"你的状态推断在我这儿不准"**,因为进行中的状态毕竟是从文件行为反推的,真实场景永远比我的想象多。
