# 复盘:问题类型与沉淀知识(2026-09-06 定稿,覆盖 1.2.0→1.2.38 全部 42 个提交)

本文把本项目踩过的坑按**问题类型**(而非时间)归档:每类给出真实事件(版本锚点)、共性根因、已沉淀的规则、现有防线。
新 bug 诊断时先对照 §7 检查单;同类型问题第二次出现即说明防线有洞,应回来补本文与对应测试。

## 类 1 · 口径漂移——"数字对不上"是这个项目最高频的 bug 族

**事件链**(几乎全是真实用户反馈驱动):

| 版本 | 症状 | 根因 |
|------|------|------|
| 1.2.14 | 仪表 3/0/3/0 与盘上 4 个运行不符 | 窗口门禁的活动度用「目录 mtime」,journal/run 写入碰不到它(与 sessions 口径各写一份) |
| 1.2.13 | 关了通知仍提示「等待输入」 | 「通知档位」与「页面显示」两个口径被混为一谈 |
| 1.2.33→36 | TASKS 总次数显示错误(5 vs 346) | 仪表加的是「视图内会话和」,而视图只有活跃+近2h;另一根因:256KB 尾窗启发式系统性少计 |
| 1.2.35 | 窗口设 180 天,项目列表只有 2 项 | 下拉从 runs∪sessions 载荷推导,纯会话项目永远不出现;且重建判定比数量——一进一出时数量不变,陈旧选项永久保留 |
| 1.2.37 | 4 天窗口列出没操作过的项目 | 用 fs mtime 判窗,被非输入写入顶新(mtime 4.0d 在窗内、最后输入 4.9d 前) |
| 1.2.38 | 选 claudeConfig 仪表 10、下方列表 0 张卡 | **1.2.36/37 改仪表口径时没同步会话列表消费者**——仪表落窗,列表仍只放行「活跃 or mtime≤2h」 |

**共性根因**:同一个统计概念(活动度 / 任务计数 / 判窗 / 过滤命中)被抄写了多份;改一处,其余漂移。最痛的变体是**上一个修复埋下下一个 bug**:改数据源口径 = 半件工程,缺消费者清单就只修一半。

**规则**:
1. 每个判定住**唯一函数**,消费者只调用不重写:`_window_hit`(项目/byCwd/会话列表)、`_user_prompt`(回显/全文/计数)、`window_activity()`(仪表+下拉单一数据源)、`sessHit`、`sessStuck`、`ALERT_ST`、`diffPaint`、`paneIn/paneOut`、前端重建判定比内容串 `PSTR` 而非数量。
2. **改任何统计口径前,先枚举全部消费者**(API 字段→下拉→仪表→卡片→tooltip→通知→测试),同一版本一起改;影响面评估是动手前的硬步骤(修 bug 第 4 步)。
3. 口径类修复的验收测试=**把参数切换多次做参数化断言**(1.2.37 的 4d/14d/45d/1d 四档:每档项目集与任务数精确匹配),不是测一次当前值。
4. 用户可见的每个数字必须有**从它核到明细的对账通路**:TASKS 命中数 ↔ 项目卡片「任务 N」之和(不变量已钉进 `test_sessions_window.py`/`test_web_api.py`);够不到的口径用 `命中/总数` + hover title 交代原因。
5. 关键数字的真值用**独立离线实现**对账(1.2.37 真机六档冒烟「API 与独立真相实现逐档全等」),不许拿被测实现验自己。

## 类 2 · 代理信号被当成内容本身

**事件**:1.2.14(目录 mtime 不随内部写入刷新)、1.2.36(256KB 尾窗外输入不可见)、1.2.37(mtime 被非输入写入顶新)、1.2.20(开场输入被超长回合挤出尾窗→孤儿组,需反向深扫回填)、1.2.24/25(子代理完成判定与主代理 stop_reason 集不同源)、1.2.10(「等授权」与「长命令仍在跑」同形)。

**规则**:
1. fs 元数据(mtime/size/目录项)只能支持**单向推断**——「内容不可能比它新」——因此只配做**负控制粗筛**(出窗⇒必无窗内内容,sound),绝不配做入选依据;「操作过/完成了/在等谁」一律看**内容自带语义信号**(记录 timestamp、type、stop_reason)。用法务上写明 sound 方向。
2. 固定尺寸窗口(尾窗 256KB)只是显示成本控制,**不许做计数与判定的数据源**——计数走全量精确 + `(mtime_ns,size)` 缓存(实测全库 111MB 仅 0.2s)。
3. 两种解释无法区分时(等授权 vs 长命令):**界面标明「疑似」,不硬判**;错误注入信号要单列(`6ec5faf`:`<synthetic>` 判 error 而非绿色完成)。启发式误报的代价设计成「只是一条可关的通知」。

## 类 3 · 显示层砍数据源(铁律 7 族)

**事件**:1.2.11(后端给 30 行日志前端又 `slice(-15)`;通知回执 90 字;渲染异常 80 字)、1.2.12(等待行 300 字硬裁无展开入口,真实消息 1559 字)、1.2.15(OUT 只展示单块,「每次只看到最新一条」)、1.2.18(_turn_texts 只收 text 块→「每行以冒号收尾之后没内容」)、历史各版「只裁不展」复发。

**规则**(CLAUDE.md 铁律 7 已固化,此处记推导逻辑):
1. 裁切合法的唯一形态:**摘要与全文入口在同一行,展开即全文**(details + data-src 懒拉 + FULL 缓存)。
2. 数据源给了多少就展示多少;要省空间用**限高滚动**,不是限条数/限字符。
3. 数据源有硬上限时**上限必须写到界面上**(「近 N 行·单行≤M 字」「⚠ 该步已超出转录留存范围」),否则用户把留存边界读成"数据撒谎"。
4. 收集内容要含**语义全集**:只收 assistant text 会丢工具活动,而工具回执往往才是答案本体(冒号收尾 bug);未回执行显式标「未回执」,不静默消失。

**防线**:`test_waitline_full.py`、`test_fulltext_drawer.ts`(裁切残留清零断言)、`test_turn_detail.py`(冒号后可见/时间序/去重/截断标注)。

## 类 4 · 前端重建契约与「静默失效」

**事件**:VER 取 `$('wfo-ver')` 但模板只有 `name=` → 恒 null,「部署自动刷新+版本角标」静默失效**多版**才被发现;1.2.13 给告警徽标加 `AD(1.8)` 每轮变字段 → 冻结卡 diff 必失配 → 「点开即关」复发,被无头桩当场拦下;1.2.16 后台标签页 setInterval 被节流到 ~1 次/分钟(真实反馈「切回页面看不到最新执行信息」);1.2.18 `<p.idle>` 无 data-rid 永不被清理;outerHTML 后 ref 未同步抛 NotFoundError 打断整轮渲染伪装成"链路中断";1.2.23 重建丢滚动锚点;1.2.6 筛选状态不持久化。

**规则**:
1. 卡 HTML 字符串只许含**每轮稳定字段**;时间一律 `fmtC(epochMs)`,绝不内嵌逐秒/逐相位值——diff 失配重建 = open/滚动/选中全丢。
2. 重建状态契约(身份保持、open/滚动快照、ref 同步、空态对称清理)全住在唯一实现 `diffPaint` 里;新卡片区直接复用,勿复制循环。
3. **不假设浏览器规范之外的行为**:轮询驱动必须同时挂可见性补扫(`catchUp`),新增任何定时刷新同理。
4. **静默失效是最坏 bug 形态**(不报错、只是永远没生效,curl 验证法覆盖不到):契约只有「真起浏览器场景」才能证伪 → 前端逻辑一律无头桩加载**真实编译产物**断言(1.2.18 入库 tests/,历史上 t1..t8 散写 /tmp 重启即绝迹,复现能力每次重造)。
5. 重构以**黄金快照逐字节一致**为零漂移证明;故意改文案才 `UPDATE=1` 重录并在提交注明。多语文案对齐测试有假阳性前科(fr 双引号孤例骗过对齐脚本)——新增文案查四语字典用同一个精确断言。

## 类 5 · 部署 / 常驻进程 / 版本链

**事件**:2026-09-04 裸 `$CLAUDE_PLUGIN_ROOT` 不被展开 → 服务从源码目录而非安装副本启动;1.2.10→1.2.11 升级后 guard 循环仍钉旧 cache 路径(记忆库 `xray-guard-loop-pins-old-version`),此后每次部署提交都写「先杀旧 guard+server 防拉旧版」;npm 通道产物陈旧风险(`bin/install.js` 编译产物)。

**规则**:
1. 运行时加载的是 **cache 副本**,不是仓库;常驻进程有两把:server 与 **guard 看护循环**——它探测到服务掉线会从**自己的运行路径** setsid 拉起,杀 server 不杀 guard 会被旧代码原地复活。升级动作顺序固定:杀 guard → 停 server → 从新路径起 server → 新路径起 guard。
2. 部署冒烟四件套:`/api/runs` 200 结构不变、**页面 ver == api ver**(前端产物已换)、`diff -r` 安装副本 == 源码、`ps -o command` server/guard 两 PID 都指向新版本目录。
3. 版本三处同步(plugin.json == package.json,`test_packaging.py` 钉死 + 打包清单/组件表核对);「每次更新 = 版本 +1」无例外,文档/规则改动也算。

## 类 6 · 过程方法论(已被验证有效,继续执行)

1. **六步 bug 流程的价值在「复现是修改的准入门槛」**:每条修复都先有 RED(= 复现用例本体,不另起链路),且 RED 精确命中用户症状数字(1.2.38:「仪表 4/列表 1」→「仪表 10/列表 0」现场取证;1.2.13:先证明推送通道零发送,才锁定页面显示)。"阅读代码看出原因"不算复现;双向确认(消除因→症状消,恢复因→症状现)才算根因。
2. **修复要覆盖同一根因的全部触发路径**(1.2.18 把四处自造 JSONL 读取收编成 `jsonl.py`;1.2.38 判窗单点三处共用),不满足于当前症状消失。
3. **提交信息是知识载体**:真实反馈原文 + 实测数字(「151 vs 127」「25/37 会话少计」「mtime 4.0d/输入 4.9d」)+ 版本链。本文档即从提交史沉淀——写提交信息时按此格式,复盘才付得起。
4. **fixture 钉泛化,真机钉适配**:数据格式在变(转录字段、目录形态),每次部署仍跑真机冒烟 + 与独立离线真相实现对账;涉及用户配置的操作(如切窗口)测毕恢复原值。
5. **界面诚实原则**:不确定就说不确定(「疑似」「命中/总数」「⚠ 超出留存」「回合已完 ≠ 等待输入」),把判定分歧摆到界面上,用户就不会拿它当"数据不准"来报 bug——类 1/2/3 的用户反馈,一半根子在界面上没说清口径。

## 7 · 一页检查单(后续开发逐条对照)

- [ ] 动的是某个**统计概念**(计数/列表/门禁/过滤)? → 先 grep 该判定的全部消费者,同版本一起改;加「参数切换多次」参数化测试。
- [ ] 想把 **mtime/size/尾窗**当依据? → 写出它的 sound 方向;方向只支持负控制的,只许做粗筛。
- [ ] 想**截断**任何东西? → 同一行必须有展开即全文的入口,否则违规(铁律 7)。
- [ ] 动**前端**? → `python3 frontend/build.py` → 黄金逐字节 → 无头桩契约测试;新字段进卡 HTML 前问「它每轮变吗」。
- [ ] 新**定时/轮询**驱动? → 必须配可见性补扫路径。
- [ ] **部署**? → 版本+1 → 杀旧 guard+server → 新路径起 → 四件套冒烟。
- [ ] 新**等待成因/通知类型**? → 四处同步:`main_state` + `wlab`/`sessStuck` + `notify.WAIT_ZH` + i18n 四语。
- [ ] 修的是**用户报的数**? → RED 用例用真实反馈数字;真机拿独立实现对账;动过的配置恢复原值。
